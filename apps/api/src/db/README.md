# apps/api/src/db

The Drizzle schema, migrations and connection pool live here, inside the API
application. There is deliberately no separate `packages/db` workspace: exactly
one service writes to this database, so a shared package would add a build
boundary without buying isolation.

Arrives in P1 (see `PLAN.md`):

- `schema.ts` — venues, rooms, equipment_types, users, bookings,
  booking_line_items, payments, audit_events
- `migrations/` — generated by `drizzle-kit generate`
- `0000_extensions.sql` — `CREATE EXTENSION IF NOT EXISTS btree_gist;` must run
  before the `no_room_overlap` exclusion constraint is created
- `client.ts` — pg Pool + Drizzle instance

The room-overlap exclusion constraint and the equipment sweep-line query are
hand-written SQL in a migration, not Drizzle DSL. Drizzle does not model
`EXCLUDE USING gist`. See ARCHITECTURE.md, "Concurrency Strategy".
